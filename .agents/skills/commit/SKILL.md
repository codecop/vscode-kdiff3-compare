# Commit

## Commit rules for this project

Format:

```
git commit -m <Commit message here>

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

Rules:

- Always use `git commit` - never any other way to commit changes
- Footer mandatory: every commit ends with the `Generated by Mistral Vibe.` and `Co-Authored-By` trailer (after the single-line message)
- Commit often after each increment - small, frequent commits instead of big batched commits
- Push every commit immediately with `git push origin main`
- NEVER change history in version control. This includes:
  - Never do `git reset --hard`
  - Never do `git rebase`
  - Never do `hg strip`
  - Never do `hg rebase`

Example:

```
git commit -m "Adds user authentication feature." -m "Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>"
```

## Message format

- The commit message is always a single line: one sentence, present tense.
- It starts with a capital letter and ends with a full stop.
- The sentence describes the state of the system after this commit is applied, e.g. `Adds folder comparison to the KDiff3 compare command.`
- Logically unrelated changes go into separate commits — never bundle them into one.

## Trunk-based development

- Work directly on `main`: no feature branches, no pull requests from branches.
- Commit on `main` and push every commit immediately with `git push origin main`.

## Push

- Plain `git push origin main` works everywhere — locally and in the cloud sandbox. In the sandbox the GitHub connector's token is injected automatically via the sandbox proxy, so no manual token handling is needed.
- Sandbox setup (connector in Mistral Studio + Mistral GitHub App installed on the GitHub account with Contents: write): see [CONNECT-MISTRAL.md](../../../CONNECT-MISTRAL.md).
